# Local optimization 00.46: submission batching and redundant reset dispatches

## Physical baseline

00.45 still falls to 31.92–33.17 VI/s against 50.01 PAL in the retrieved Tennis
session, despite reducing maintenance pixels by 56.94% overall. One slow interval
contains 2,918 batches, with 2,031 texture hazards and 799 framebuffer changes.
The focus is the cost of many small passes, not additional texture memory.

## Changes included

- Keep native and upscaled work from the same batch together before evaluating
  routine submission. Their ordering, barriers and resource retirement remain
  unchanged; explicit FullSync and buffer-reuse submissions remain intact.
- Coalesce microscopic batches when the GPU queue has drained, with an idle
  age threshold of 250 microseconds or four completed logical passes. Retain the
  eight-pass and 256-primitive limits and the one-millisecond age threshold.
  Thresholds are evaluated when queue maintenance runs; they are not a promise
  of wall-clock latency independent of CPU scheduling. Idle notifications and
  explicit synchronization retain their existing progress behavior.
- Skip the indirect-buffer reset dispatch in texture-only passes, which never
  bin or shade primitives and therefore do not modify those counters. First-use
  initialization and every real render pass retain their reset dispatch.

No shader code, graphics quality, particles, resolution, audio or resource guards
were changed. GPU timestamp queries remain off. `[rdp-submit-batches]` reports
RDP submissions, native/upscaled passes, primitives, paired passes and skipped
reset dispatches. `NPS64_RDP_REFERENCE_SUBMISSIONS=1` selects the previous route
for native equivalence checks, while keeping the 00.45 active-row changes.

## Change rejected before upload

A same-format 16-bit texture-range refinement was also implemented and tested.
The extended deterministic sequence exposed two mismatching images. Repeating
the reference matched the reference exactly; removing the refinement eliminated
the difference. Its precise failure mechanism has not been established.

That refinement was removed completely from source preparation and the final
core. The final ELF is checked for absence of its experimental control and log
strings. Its development evidence remains in ignored build artifacts only.
Existing texture/framebuffer hazard checks remain unchanged in 00.46.

## Local validation

A Tennis state was retrieved read-only from the PS4 test-save directory. It
passes the normal state header/core/ROM/size/checksum validation before loading.
Both comparison runs load it at the same emulated frame and receive identical
frame-indexed A/B inputs, independent of UI polling speed.

- Submission policy: 13,122 progress/deadline cases pass with ASan/UBSan.
- Final reference comparison: 259 consecutive readback images match exactly by
  byte hashes, including animation and controller-driven play. No ASan memory
  errors or Vulkan validation errors. Existing unrelated core UBSan diagnostics
  are not claimed fixed.
- At the common 240-image reporting boundary, both runs draw exactly 3,005 native
  passes, 2,542 upscaled passes and 110,779 primitives. RDP submissions decrease
  from 1,245 to 988 (20.64%); the final route skips 67 redundant reset dispatches.
  Counters are drained at explicit image boundaries for this comparison.
- These are native Vulkan functional/work-count results, not PS4 FPS results.
  No 20.64% FPS gain is predicted from a 20.64% reduction in RDP submissions.
- Patch idempotence, Python compilation and `git diff --check` pass.
- PS4 ELF/BSS mapping and all 28 package checks pass. Manifest confirms GPU
  timestamp profiling is disabled.
