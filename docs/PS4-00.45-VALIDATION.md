# Local optimization 00.45: conservative active rows and texture-only batches

Physical 00.44 established that framebuffer changes and texture/framebuffer
hazards dominate batch fragmentation in the slow Tennis replay intervals. The
lowest non-startup interval in that session was 40.95 VI/s against 50.01 PAL,
with 1,706 nonempty batches: 1,115 texture hazards, 515 color framebuffer changes,
55 capacity flushes and 21 explicit syncs. These are interval counts, not counts
per individual frame. A different interval had 2,182 batches, including 1,962
color framebuffer changes. TMEM capacity did not fill. More allocated texture
memory is not justified by these counters.

## Implementation

1. While producing span jobs, accumulate the earliest potentially affected row
   for the current batch using the same primitive/scissor Y intersection. Retain
   a guard scanline and round down to four rows. Reuse this cached bound rather
   than scanning the primitives again on each maintenance pass.
2. Restrict pre/post upscaled-domain maintenance to that conservative row range
   for aligned 16-bit buffers. Color and depth addresses advance equally; the
   previous upper bound remains unchanged. Odd framebuffer widths remain word
   aligned. Other formats, unaligned buffers, empty bounds and supersampled
   readback retain the established full-range maintenance path. External domain
   maintenance and VI are unchanged.
3. Retain pending TMEM uploads across a framebuffer change when no primitive is
   queued. Upload order and texture instance indices remain unchanged. A real
   queued primitive still forces the existing flush before the framebuffer
   changes. No previously computed texture content is reused without checking
   its validity; this retains the uploads already in the current FIFO batch.

No shader was rewritten, no barriers/FullSync were removed, no particle effects
were dropped, and internal 2x resolution is unchanged. A new specialized shader
is deferred until this reduction in maintenance work is measured physically;
adding another dispatch without evidence would add work rather than establish
an optimization.

`[rdp-active-rows]` reports full vs processed maintenance pixels and retained
texture-only batches. It measures work removed, not FPS gained. The native-only
reference switch `NPS64_RDP_REFERENCE_BATCHES=1` disables both optimizations for
image equivalence comparison. GPU stage timestamp queries remain off.

## Validation

- ASan/UBSan active-window test: 239,303 windows, address equivalence for every
  retained row, odd strides, color/depth aliasing, alignment and format fallbacks.
  Run with `bash build/run-local.sh bash scripts/test_rdp_update_window.sh`.
- Native Tennis reference vs optimized: 765 consecutive readback images match
  byte-for-byte hashes, including menus and animated rendered geometry. Zero
  image mismatches, ASan memory errors or Vulkan validation errors. These are
  functional checks on native Vulkan, not PS4 performance measurements. Existing
  unrelated core UBSan warnings are not claimed fixed.
- Across the optimized native run, maintenance traversed 143,979,008 rather than
  150,943,232 pixels (4.61% fewer overall in that startup/menu sample; savings
  depend on the scene). This is not a prediction of FPS gain in PS4 replays.
- Patch idempotence and `git diff --check` pass.
- PS4 ELF/BSS and all 28 package checks pass. Manifest has stage timing disabled.
- Package: `/data/pkg/NPS64-Vulkan-Game-Test-00.45.pkg`; full upload readback hash
  recorded in `build/corrections-00.74/upload-00.45.json`. 00.44 remains available.
