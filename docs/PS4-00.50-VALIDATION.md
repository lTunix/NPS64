# Local compatibility test 00.50: Mario Kart flicker and forced session pause

## Reports and reproduction

The user reports flickering graphics, particularly in Choco Mountain, after the
00.47–00.49 optimizations, and supplied a state at the affected scene. The state
`rom-785284ea9f7bb828.slot0.state` was retrieved read-only from the PS4 test-save
directory (MDTM 20261117023058). It matches the locally available Mario Kart 64
PAL dump. The normal state checksum/core/key checks pass. A debug image confirms
the Choco Mountain race, lap 2/3.

Native Vulkan did not reproduce the visual flicker. Comparing the optimized tile
path with `NPS64_RDP_REFERENCE_TILES=1` produced 426 identical consecutive images.
This does not rule out a PS4-specific or accumulated renderer-state problem.

The separate unwanted pause IS explained by the existing diagnostic limit. The
physical log contains `LIMIT reached elapsed_s=600.019 VI=29950`, followed by a
stop at 613.585 seconds with `limit_reached=1`. The frontend deliberately kept
forcing `paused=true` after expiry, including after an attempted manual resume.

## Changes

- Mario Kart 64 selects full native/upscaled tile dispatches instead of 2D tile
  pruning. Detection uses the exact normalized 20-byte cartridge title and
  recognizes all three dump byte orders; it does not depend on the file name.
  This is a targeted compatibility trial, not a proven root-cause correction.
- Other games retain active tile pruning. The choice is reset for each load,
  before the renderer receives the game's commands. Active-row maintenance,
  batching, FullSync, CPU/Jaguar optimization flags, quality and 2x are retained.
- The PS4 diagnostic frontend defaults to no session cap (`0`). The expiry check
  only applies to explicitly positive limits. Short native diagnostic caps are
  still available to test scripts that define them intentionally.
- Incremental PS4 core compilation now uses the same configured Jaguar/O3
  options as the full build path, rather than compiling touched units at O2.

An alternative partial-readback copy was explored and discarded. The existing
path also contains atomic read-modify-write publication and an MFENCE; no actual
ordering defect was established. The cached-copy experiment, its helper and
builder hooks are NOT included. Graphics and driver synchronization remain as
before, apart from selecting the established full-tile path for Mario Kart.

## Validation

- Cartridge-title test passes under ASan/UBSan for all dump orders, other games,
  invalid magic, null and truncated input.
- Automatic Mario Kart compatibility selection is confirmed by
  `[rdp-compat] full_tiles=1 header_match=MARIOKART64`.
- 407 consecutive images from the compatibility run match the full-tile reference;
  no ASan memory errors or Vulkan validation errors. Existing unrelated core
  UBSan diagnostics are not claimed fixed. Native FPS is not PS4 performance.
- A native default-cap test advances the frontend clock by 700 seconds, manually
  pauses/resumes, continues rendering for 40 more images, and exits normally.
  Log: `wall_limit_s=0.000`, stop at 723.185 seconds, `limit_reached=0`.
  This simulates elapsed time; it is not a physical 12-minute PS4 test.
- PS4 ELF/BSS/deferred-constructor checks and all 28 package checks pass.
- `git diff --check` and Python compilation pass.
