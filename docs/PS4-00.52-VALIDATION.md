# PS4 test 00.52: Mario Kart depth correction

Status: corrected and confirmed by the user on PS4, with no observed performance regression. No public release.

## Cause and scope

F3DEX/F3DLX 0.95 combines extended vertex encoding with the original Fast3D
`RDPHALF_1` perspective-normalize command. The HLE walker selected extended
decoding and ignored that command. In the supplied Mario Kart 64 PAL state,
terrain was transformed with `perspNorm=65535` instead of the game's value `87`.
The resulting loss of depth precision lets distant surfaces appear through walls.

The fix accepts the old perspective command for the already detected 0.95
microcode family. It is not a forced depth value or a ROM-name exception.
Later GBI 1 builds retain their MOVEWORD behavior. Inline texrect HALF commands
remain texture coordinates. Vulkan rasterization, HLE execution and batching
remain enabled; no LLE fallback or extra GPU work is introduced by this fix.

## Validation

- The real-walker regression test passes for 0.95, later GBI 1, plain Fast3D,
  texrect tails and MOVEWORD (`scripts/test_gbi1_persp.sh`).
- Existing bounded microcode detection and cull-format tests pass.
- The same PS4 slot-1 state reproduces the fault with uncorrected HLE; the
  original microcode through CXD4 provides a clean visual reference after redraw.
- Corrected software HLE and corrected Vulkan at 2× both show a clean tunnel
  at race time 1:32.15. The 16-presentation Vulkan burst retains the old state's
  corrupted framebuffer/depth for the first few presentations, then clears it
  as the buffers are redrawn (indices 4–15 are clean). Do not claim a clean
  restored framebuffer on the very first presentation.
- No new ASan memory errors or Vulkan validation errors in the captured run.
  Existing dynarec UBSan diagnostics are still present and are not claimed fixed.
- PS4 ELF/OELF layout checks and all 28 package checks pass; extracted payload,
  icon and SFO verified. This is a diagnostic capture build, not a performance
  benchmark or evidence of long-session stability on hardware.
