# Local optimization 00.48: submission coalescing, even-width row alignment, and bounded indirect reset

## Physical baseline (00.47)

In physical PS4 testing of `00.47` (`Mario Tennis (E) (VC).z64` at 2x resolution,
PAL target ~50.01 VI/s), the 31–34 FPS drops from `00.45`–`00.46` were eliminated:
49 of 53 gameplay intervals ran at >= 48 FPS (median 49.57 FPS, 0 intervals below
45 FPS). However, replay sequences still dipped to **45.17–45.64 FPS**
(`core_ms=20.901–21.877 ms`, `rdp_ms=9.813–10.776 ms`) against the 19.994 ms
PAL VI budget.

Tracing the replay frames revealed that Mario Tennis alternates 80+ times per
3D frame between `fb=0x000400` (`depth_addr`) and `fb=0x3a0000` (color buffer),
drawing 1 primitive per pass (~1,881–2,225 `set_color_framebuffer` flushes/s and
383–490 `vkQueueSubmit`/s).

## Changes included in 00.48

- **Microbatch submission coalescing (`src/rdp_batch_policy.h`)**:
  - Raised the per-submission micro-pass limit from `8` to `16` passes (and from
    `4` to `8` when the GPU queue has drained), staying well within
    `Limits::NumSyncStates` (`32`), while retaining the 256-primitive cap and
    250 us / 1 ms age deadlines.
- **Even-width active-row alignment (`src/rdp_update_window.h`)**:
  - `nps64_rdp_update_window` previously rounded `first_row` down to a multiple
    of 4 (`first_row &= ~3u`), adding up to 3 extra full-width rows per `Pre`
    and `Post` domain update dispatch. For even framebuffer widths (`(width & 1u) == 0`,
    which covers 384/320/256/64), every row offset `first_row * width * 2` is
    already 4-byte aligned without rounding (`if (width & 1u) first_row &= ~1u;`).
- **Bounded `clear_indirect_buffer` (`scripts/patch_rdp_active_rows.py`)**:
  - Full 256-slot initialization (`4` workgroups) is retained when
    `indirect_dispatch_buffer` is created in `ensure_command_buffer()`. Subsequent
    render passes clear only `((stream.static_raster_state_cache.size() + 63) / 64)`
    workgroups (typically `1` workgroup instead of `4`).

## Change rejected before upload

- Skipping the `depth_addr` copy in `submit_update_upscaled_domain(ResolveStage::Post)`
  when `!fb.depth_write_pending` caused 2 image mismatches (frames 138–139) because
  `Post` also synchronizes `vram_reference16` after earlier 1x/CPU writes. It was
  completely removed and is absent from the final core and PKG.

## Local validation

- `scripts/test_rdp_update_window.sh`: **239,303** active-row windows and
  **2,520,320** 2D tile-binning oracle checks pass under ASan/UBSan.
- `scripts/test_rdp_batch_policy.sh`: **13,122** submission policy cases pass.
- Deterministic Mario Tennis state replay (`build/corrections-00.74/validation-00.48.json`):
  - **259 / 259** consecutive readback frames match `batch-tuning-final.log`
    bit-for-bit (`image_mismatches: 0`), with 0 ASan memory errors and 0
    `VK_LAYER_KHRONOS_validation` errors.
  - At the common 240-image boundary (`SUBMIT_AT_FRAME 240`): identical passes
    (`3,005` native, `2,542` upscaled) and primitives (`110,779`), with
    `submissions` reduced from `988` to `922` and `processed_pixels` reduced from
    `139,178,944` (`00.47`) to `136,537,024` (`00.48`).
- Packaging and PS4 FTP transfer:
  - `out/NPS64-Vulkan-Game-Test-00.48.pkg` passed ELF/BSS checks and all 28
    package checks, and was uploaded and SHA256-readback verified at
    `/data/pkg/NPS64-Vulkan-Game-Test-00.48.pkg` (`build/corrections-00.74/upload-00.48.json`).
  - `00.47` and `00.46` are retained on the console as comparison/fallback.
  - No git push or public release was performed.
