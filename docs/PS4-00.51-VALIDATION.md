# Diagnostic 00.51: direct paired captures of the Mario Kart flicker

The user confirms that 00.50 still flickers and requests investigation with
screenshots. Its full-tile compatibility change is NOT considered a fix.
00.51 keeps that rendering path and adds bounded diagnostic capture only.

## Capture method

Build with `--frame-captures --gpu-present --test-updater`. The builder rejects
combining frame capture with public release; the packager independently rejects
a capture-enabled ELF being packaged as a public release.

- A successful state load arms a burst. Resume the game to start copying frames.
- Alternatively, press L2 + R2 + Triangle while the visual problem is present.
  The chord is suppressed from the emulator's game/cheat input while held.
- Records 16 consecutive presentations, retaining repeated emulated/video frames.
- `NN-game.ppm`: completed/composited game framebuffer before the frontend HUD.
- `NN-scanout.ppm`: on PS4, the chosen VideoOut buffer after overlay publication
  and the existing store fence, immediately before submitting the flip. On the
  host test backend it is the post-overlay canvas before presentation.
- `frames.csv`: ROM key, trigger, sequence, emulation/video frame counters,
  source dimensions, internal scale and before/after hashes.
- Files: `/data/NPS64/frame-captures/capture-<clock>-<sequence>/`.
  Existing directories are never overwritten. Wait for the saved notification
  or `[frame-capture] saved=1` before retrieving the complete batch by FTP.

No extra Vulkan commands, GPU readback, VI or fences are inserted. Existing
completed framebuffers are copied to an immutable, lazily allocated RAM batch.
A separate IO worker hashes the snapshots and writes PPM/CSV after the burst.
The pool is freed after writing; shutdown joins the worker. Partial completed
batches are saved on leaving the game; an incomplete before/after pair is not
written. Busy/allocation/IO failures are reported without stopping emulation.

The optional burst reserves about 112.5 MiB and writes about 84.4 MiB of RGB
images for 1280x720 output. Copies, cache effects and background IO can perturb
pacing or the symptom itself. These are diagnostic captures, NOT FPS benchmarks.
No camera/Chiaki capture and no promotional gameplay clips are used.

## Validation and local observations

- ASan/UBSan unit test: 16 immutable pairs, correct RGB channels, repeated frame
  retention, busy rejection, partial/empty/incomplete batches, IO setup failure,
  worker restart and shutdown while a batch is pending.
- Native Vulkan compositor with the supplied Choco Mountain state: 16 paired
  presentations / 32 complete 1280x720 images. Their before/after differences
  are confined to the frontend HUD band (y=12..56). No ASan memory errors or
  Vulkan validation errors in that run. The reported PS4 flicker was not
  reproduced locally; this does not clear the PS4 presentation path.
- Software Angrylion/HLE captures were also obtained as a qualitative reference;
  different internal resolutions/backend state prevent treating these as a
  bit-exact A/B oracle. An attempted cxd4 state restore yielded no useful game
  image and is NOT a valid reference or evidence of the flicker cause.
- PS4 ELF/BSS/deferred initialization and all 28 package checks pass.
- Public capture-release combinations are rejected before packaging/publishing.
- Rendering, FullSync, audio, internal resolution, the 00.50 compatibility
  selection and the disabled automatic session cap are retained.

Artifacts: `build/kart-flicker-00.51/` (private captures, native logs, validation
JSON, packaging checks and upload evidence). Unit test:
`bash build/run-local.sh bash scripts/test_frame_capture.sh`.

trigger the burst, and notify once the saved message appears. Capture at the
moment of the defect; loading the state alone might reset accumulated state.
Retrieve only that diagnostic directory through the already authorized FTP.

Compare game/scanout pairs and consecutive images, using the CSV to distinguish
new video frames from repeated presentations. Corruption before the HUD points
to game/VI/composition. Clean game images with additional corruption after
publication point to overlay/copy handling. If both snapshots are clean while
the physical display flickers, investigate actual flip/cache/display behavior;
these files show intended scanout memory, not a photograph of the panel.
Do not infer flicker merely from camera motion or a whole-frame hash difference.
